۲) جریان کار سیستم — از سند تا سیگنال

۱
ورودی دانش

سند (PDF/DOCX/XLSX/ZIP/TXT) آپلود می‌شود؛ پارسرها با سقف ۶۴MB برای هر عضو فشرده (M10) متن را استخراج می‌کنند؛ هر سند با content_sha256 یکتا dedup می‌شود (M9).

۲
استخراج قانون

RuleExtractor از متن قوانین کاندید می‌سازد: شرایط RSI/MA ساختاریافته، مبهم‌ها صریح ثبت می‌شوند؛ همه با وضعیت PENDING ذخیره می‌شوند — هیچ قانونی خودکار فعال نمی‌شود.

۳
تأیید انسانی + جهت صریح (M4)

تو از طریق API جهت صریح (BUY/SELL) هر قانون را تعیین می‌کنی (POST /rules/{id}/direction) و سپس approve می‌کنی. جهت هرگز از اسم قانون حدس زده نمی‌شود؛ قانون بدون جهت هرگز ووت نمی‌دهد (fail-closed).

۴
داده و مدل

MT5 کندل‌های XAUUSD M1 می‌دهد؛ DatasetPipeline ویژگی‌های فقط-گذشته می‌سازد؛ ModelTrainer لِیبل triple-barrier می‌زند و Logistic Regression / Random Forest آموزش می‌دهد؛ شواهد Walk-Forward با purge 24 + embargo 12 به مدل می‌چسبد.

۵
دروازهٔ promote

ModelRegistry با ۹ گیت: تأیید شواهد WF، Brier، هزینه‌ها، امضای HMAC — مدل candidate فقط با عبور همهٔ گیت‌ها active می‌شود؛ مدل فعال وسط run عوض نمی‌شود.

۶
سیگنال live

Worker هر ۳ ثانیه: کندل بسته‌شده → ویژگی‌ها → SignalGenerator (ووت‌های جهت از قوانین تاییدشده + مدل فعال) → consensus → RiskEngine fail-closed → TradeSignal ثبت می‌شود. چون EXECUTION_MODE=SIGNAL_ONLY است، مسیر سفارش از سیگنال جداست.

۷
حفاظت و ممیزی

هر اتفاق مهم در AuditLog ثبت می‌شود؛ retention پیش‌فرض خاموش (هیچ رکوردی بدون پنجرهٔ صریح اپراتور پاک نمی‌شود)؛ busy_timeout مانع خطای «database is locked» در تصادم API/worker است.

۳) نرده‌های ایمنی (Safety Rails)

EXECUTION_MODE=SIGNAL_ONLYهیچ مسیر کدی به mt5.order_send نمی‌رسد؛ ۱۲ دروازه به‌صورت زنجیره‌ای گیت می‌زنند.
تأیید انسانی قوانینقوانین با PENDING متولد می‌شوند؛ فقط APPROVED ووت می‌دهند و جهت‌شان صریح است (M4).
RiskEngine fail-closedنبود حساب/نقل‌قول/کانترکت = رد سیگنال؛ زیان روزانهٔ account-wide ۳٪ (تصمیم ۳ یا ۵٪ با اپراتور باز است).
جلوگیری از نشت دادهویژگی‌ها فقط-گذشته؛ walk-forward با purge+embargo؛ لِیبل با اسپرد.
DemoExecutor قفلDEMO_TRADING_ENABLED=False؛ تنها caller واقعی order_send؛ خروجی نامشخص → reconciliation deals-based.
آفست زمانی MT5+۳h فقط وقتی سرور بروکر مطابقت دارد اعمال می‌شود؛ تایم‌استمپ آینده/کهنه رد می‌شود.

هیچ ادعای سودآوری اثبات‌شده‌ای وجود ندارد؛ سبز بودن تست فقط درستی نرم‌افزار را ثابت می‌کند، نه لبهٔ معاملاتی.

۵) نکته‌های کلیدی هر جزء

Rules (قوانین)

هر قانون: شرایط ساختاریافته (RSI/EMA/SMA)، direction صریح (BUY/SELL/NULL)، دسته (entry/exit/filter/risk)، scope نماد/تایم‌فریم، منبع (سند+صفحه)، وضعیت تأیید. ژنراتور فقط شرایط شناخته‌شده را قبول می‌کند؛ شرط ناشناخته = قانون غیرفعال (fail-closed).
